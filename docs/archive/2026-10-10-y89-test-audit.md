## Dispositions and gate answers

- G6: update the existing literal ordinary plan expectation. It now names
  optional verdict feedback and the failed candidate gate's bounded return
  route. Keep its unsupported graph refusal and native successful control.
  Expected nodes, input types and routes come from the fixture configuration
  and the current architecture contract. No additional scenario is needed.
- G7: add the ordinary repair-to-approval scenario. A real gate first fails;
  its repair supplies the missing fixture file. Then a first reviewer blocks
  and the final reviewer passes. The panel must still return for repair.
  A fresh candidate passes the gates and both seats and reaches approval.
  The existing round trip covers landing, proof, usage, audit and cleanup;
  it cannot detect the loss of an earlier block behind a passing final seat.
  Assertions use CLI inspection, read-only store queries and canonical git.
  Node order, files, bytes, failed/blocked/complete outcomes and one blocking
  round come from the fixture and spec. Execution comparisons only establish
  predecessor and repair-source agreement. Sabotage: retain both schedulers,
  discard the cumulative block, or omit the failed gate route or its feedback.
- G8 missing publication: extend the existing review error and successful
  same-head retry control. A missing publication has no judgment, route or
  typed output and starts no repair. Expected absence comes from the model
  script, which publishes nothing, and the spec. Its observers are the store
  and status history. Sabotage: treat no publication as a failed judgment.
- G8 held blocking edge: strengthen the existing teardown scenario with a
  restart. The model holds a request after publishing the literal P1 block.
  The quick workflow's approval proves that scheduling continued without
  starting repair. Kill the daemon while this model latch still holds.
  Before restart, the store proves the review is running, has no result and
  has unchecked teardown; the durable fail publication was already observed.
  Reconciliation must leave exactly one interrupted review with a blocked
  result and checked teardown, then exactly one repair. A second fixture
  latch holds that repair while counts are inspected. Pinfold proves that
  the original seat's box is gone. No new binary barrier or ownership path
  is introduced. Sabotage: route from publication, bypass teardown, or keep
  both schedulers. The same project supplies the allowed control: the original
  blocking result starts repair once its ownership has been reconciled.
  The existing held pass restart proves publication preservation and refusal
  of a second publication; it cannot expose duplicate blocking back edges.
- G8 infrastructure error: extend the existing refused gate-box start and
  same-head successful gate retry. The error has no judgment or output and
  starts no repair. Expected absence comes from the host pinfold wrapper's
  refusal and the spec. Store and status are the observers. Sabotage: route
  an infrastructure error as a failed judgment. The missing-publication
  scenario exercises a different mechanism: a successful runner with no
  published decision, rather than an external execution failure.
- G8 held pass publication: retain its assertions and add the empty panel
  block list to its literal verdict value. The fixture publishes a pass;
  the block list must be empty. Its original reference and registration
  preservation assertions remain.

## Implementation evidence

The candidate/review scheduler now walks admitted routes. Current checks
select exact identities through Y-88's one eligible-result predicate. New
admissions use durable result outcomes to select the route. Each intermediate
seat carries its panel's blocking check identities into the next seat's
inputs; the final result declares blocked even if that seat itself passes.
Gate failures and blocking panels record the new repair execution and its
feedback before any effect. Ordinary scheduling no longer writes repair
intent into attempt.next. Round accounting and starting repair share a
transaction. Pending edits outrank repairs and capture the current ticket
body in the new execution.

Older complete-only admissions translate their ordinary routes in memory.
They use their existing current checks as decision evidence, within the same
route scheduler. Historical panel suppliers without results remain unknown;
existing checks can supply exact verdict values without inventing producer
results. Admission and prior execution rows are not rewritten.

Candidate gate infrastructure failures, including timeout evidence, have no
failed judgment route. Published proven review judgments retain their existing
meaning across runner failure or interruption. Landing and its gates remain
queue-controlled. Arbitrary graph admission remains refused. There is no new
schema, dependency, worker grant, controller, lease or recovery path.

including compilation of the changed host e2e scenarios. Runtime acceptance
and sabotage validation remain for the operator's host gate.
