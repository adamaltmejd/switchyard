Measured on yard-sthlm (Debian 13, 4 CPUs, 10 GB, podman 5.4.2, pinfold
0.0.6, Pi 0.87.1), debug build, warm base image, `--test-threads 4`, one

About 24 minutes, against the 5-minute target in `AGENTS.md`. No scenario
waits out a clock; the time is boxes.

Where it goes:

- A scenario is 25 to 45 seconds: a daemon, a project, and two to eight
  boxes. Each project builds its own image (`yard-<key>`), and the first
  `box up` of a new image spends 5 to 20 seconds in podman's
  `storage-chown-by-maps` for `--userns=keep-id`; four at once contend
  for it.
- `cargo test` runs the fifteen test binaries one after another, so each
  file's slowest scenario gates the next file.
- A later `box up` from a built image is about 0.4 seconds; a cached image
  build about 3.5 seconds.

Levers, unmeasured, in the order they look cheapest:

1. Run the binaries at once, or fold the files into one binary, so four
   threads stay busy across guarantees. Expected near the sum divided by
   four, about 6 minutes.
2. One image per machine rather than per project for the test fixture,
   so the chown happens once per run.
3. More threads on a host with more cores; memory per box is the limit.

Found by writing the inventory, each now covered: approval items outliving
a digest or ticket change; a landing re-reading policy with the
configuration it started with; `refs/yard/import` left behind by a refused
sync; a host landing gate taking its landing's lock twice, and the lock
descriptor leaking; a restart losing the interrupted execution's session; a
nudge lost behind a candidate that then landed; the harness downing other
tests' boxes on teardown. Pi validates tool arguments against the schema
before calling, so Yard's own validation is reached only by a direct call
on the route.
