# Y-75 assertion audit

This is the test-audit gate for Y-75, not a release sweep. Y-66 is landed
on this branch at b22ab00. Scope comes from the October 9 redesign plan
and the ticket's agreed handoff. The binding G7 clause changes with the
implementation. Claude and Codex readers are unchanged.

The new scenario is
`pi_unknowns_and_interrupted_resume_usage_remain_execution_local` in
`g07_usage.rs`. It runs the real daemon and Pi in real boxes against the
scripted host chat-completions fixture. The fixture supplies token counts.
A host pinfold wrapper removes usage from the first execution's assistant
message frames and cost from the second's. It streams all other frames,
keeps stderr and preserves the real child's exit status. This explicitly
tests absent adapter input: Pi normally supplies its own catalog cost even
when the provider supplies none. It does not establish provider billing.
The third execution receives explicit zero tokens and reports zero cost.

| Block | Disposition and G7 clause | Sabotage | Observer and outside expectation |
|---|---|---|---|
| First completion with absent usage | Add: no report means null, unreported and unknown | Coalesce missing fields to zero | CLI execution JSON; the host wrapper removes all assistant usage reports |
| Interrupted resumed turn | Add: new-message increments survive interruption, with partial coverage and absent cost | Save usage only at settlement, or count session history | CLI execution JSON; one fixture reply reports the fixed token counts, the next request is held and unanswered; resumed identity names the previous execution |
| Reopen after interruption | Add: recorded increments survive reopening | Discard or replace partial observations during reconciliation | CLI execution JSON equals the pre-reopen record; the fixture remains held |
| Resumed explicit-zero completion | Add: zero is numeric and successful full coverage is complete | Discard zero or record session cumulative totals | CLI execution JSON; every new fixture reply supplies zero tokens, Pi reports zero cost, and resumed identity names the interrupted execution |

The second execution's real box is ended through pinfold while its next
model reply is held. EOF lets supervision drain every already reported
frame, without racing operator stop against pending pipe delivery. The
stopped item must name `failed`, the execution must be failed, and the host
latch must still be held. Only after its ended record is observed does the
test kill and reopen the daemon. This is not a daemon crash scenario.
No unheld running point is used as crash evidence.

The existing G7 landing block observes fresh Pi totals after ordinary
completion. The Y-66 blocks observe fresh Codex totals and migration.
Neither exercises absent Pi frames or Pi accounting through interrupted
resume. They remain. The explicit-zero resumed completion is the positive
control in the same project, with nonzero session history behind it.
No existing assertion or guarantee clause is removed or weakened.

The operator's list is empty. The four gate questions are answered above.
Six fixture lines are replaced; no assertion is removed. The binary
replaces 26 lines. Binary removals replace zero defaults and the
blanket downgrade of resumed Pi completeness; no feature is deleted.

`cargo fmt --check` and `cargo clippy --all-targets --locked -- -D warnings`
