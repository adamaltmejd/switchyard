# Y-155 test-audit Gate

The existing `concurrent_readers_share_capacity_and_join_exact_results_across_restart`
scenario is extended. No test is added or removed. Its original capacity,
checked restart, command access and exact join controls remain. The original
G2/G8 candidate selection scenarios and release scope through Y80 remain.

The added assertion blocks pass the Gate:

- G2: foreign and historical public finding sources refuse with the exact
  rejected identity. A committed selection survives restart once. Plan
  revision and candidate change require fresh source executions and selection.
  Sabotage: choose by prose, position or latest result, or reuse an old
  selection. The fixture repeats shared prose in another ticket and both
  declared models. Store foreign keys, Git heads and literal revisions supply
  expected identities.
- G8: malformed groups and repeated contributors refuse before a valid subset
  and two-source duplicate group publish in the same conversation and project.
  A fixture hold after publication keeps the report reserved without a result
  or approval. Completion and checked release publish one inspectable result,
  without a judgment or candidate choice. Raw findings and source rows,
  including verdicts and usage, survive revision, candidate change and landing.
  Sabotage: partially commit a refused group, drop a contributor or erase raw
  findings. Fixture bodies and reasons supply group expectations. Host store
  rows supply original finding, execution and result identities.
- G13: distinct declared model settings reach real reviewer requests. The
  picker binds the exact named eligible reviewer and join executions on the
  read-only candidate/proof. Sabotage: bind another supplier or mount the
  candidate writable. Declared model strings, the graph, Git and public source
  rows supply expectations. The original same-project writable command control
  remains.

Existing candidate picker assertions exercise candidate activation, not finding
groups. Existing join assertions establish supplier readiness, not contributor
retention or finding selection reuse. The extension uses the existing held
reviewer crash point, a held picker publication, explicit revision and a ticket
edit. It adds no timer, retry, runtime seam or second lifecycle. The scenario
keeps historical inputs while fresh same-head and changed-head inputs become
eligible; first-run publication alone cannot pass these blocks.

The G2/G8/G13 Shown by clauses are extended in the same change. No existing
guarantee or clause is weakened. No operator disposition is needed beyond this
ticket's authorized new contract. Test diff: 285 added, 12 removed lines.
Binary diff: 331 added, 17 removed lines. Removed lines are replaced fixture
and publication code, not deleted guarantee coverage.

Validation: `cargo fmt --check`,
`cargo clippy --all-targets --locked -- -D warnings`, and `cargo build --locked`.
The e2e suite and live sabotage runs were not executed: the ticket explicitly
reserves them for the sequential host landing gate after approval.
