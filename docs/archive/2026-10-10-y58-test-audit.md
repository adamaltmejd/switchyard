# Y-58 operator MCP assertion gate

Added one scenario, `operator_wait_cancellation_keeps_work_and_worker_grants_separate`.
No existing assertion was removed or weakened. This is an assertion gate,
not a release sweep. Host execution and sabotage runs remain landing work;
the worker was instructed not to run the e2e suite here.

- G1: a trusted fixture Pi extension sends an operator park tool through
  the real harness's initialized worker HTTP session. The observer reads
  its response and the store's refusal reason and unchanged parked field.
  Expected refusal and parked values come from the spec and fixture. The
  trusted stdio operator parks the same ticket and approves it for landing.
  Sabotage: route worker tools to operator dispatch. The existing G1 probe
  has no session; it cannot catch dispatch after session authentication.
- G2: the operator edits revision 1 successfully, then submits revision 1
  again through stdio. It approves the old canonical head from git,
  then the real head. Error identities, ticket and approval rows and git
  are observed from outside. Revisions and bodies come from the fixture;
  the actual head comes from git in the candidate checkout. Sabotage:
  omit identity arguments or rewrite stale errors in the stdio adapter.
  Existing CLI tests cannot catch this separate forwarding boundary.
- G6: a stdio edit adds an unknown field after its valid control
  succeeded. The response is invalid and the externally read ticket rows
  stay at the fixture's expected revision and body. Sabotage: remove
  strict operator schema validation. The otherwise valid edit then writes.
- G7: a real boxed implementer is held at its model request. Two stdio
  attention calls are armed, with a ping round trip proving each process
  continues to read requests. One wait is cancelled with an acknowledged
  request identity; another process disconnects. The hold is released and
  git and the store show the fixture's commit landed and ticket done.
  Sabotage: stop execution on wait cancellation or disconnect. CLI watch
  tests do not exercise MCP cancellation or multiple requests on one pipe.
