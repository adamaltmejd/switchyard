# E2E budget: the CLI hashed its own binary

Follows `2026-09-28-e2e-images.md`, same host and suite. That note put the
time left after images on Pi, gates and git. It was the CLI.

`api::boundary` is the SHA-256 of the running executable, computed once per
process. Every `yard` call a test makes, every `status --watch` it opens and
the daemon's start each hashed the 71 MB debug binary with `sha2` built at
`opt-level = 0`: 3.3 s of CPU per call. G1 made six such calls, and they were most
of its 25 seconds. The 2-second steps in its timeline were the idle scheduler's
fallback tick, not waits.

`[profile.dev.package.sha2] opt-level = 3` brings a call to 0.36 s (no
SHA-NI on this CPU; `sha256sum` takes 0.16 s on the same file). Release
builds were never affected.

| Run | Wall | User CPU |
|---|---|---|
| before (previous note) | 10.0 min | 25.3 min |
| `sha2` optimized in dev | **6.5 min** | 4.2 min |
| G1 alone, before / after | 25.1 s / 9.9 s | |

## Where the 6.5 minutes go

Every pinfold call, timed from a wrapper on `PATH`; about 1550
thread-seconds in all:

| Call | n | Mean | Total |
|---|---|---|---|
| `box up` to ready, first from its image id | 62 | 8.8 s | 546 s |
| `image build` | 62 | 5.3 s | 326 s |
| Pi runs (`box exec`) | 109 | 2.4 s | 263 s |
| `box up` to ready, image id seen before | 81 | 1.4 s | 111 s |
| other `box exec` | 109 | 0.6 s | 67 s |
| `box list`, `stat`, `prune`, `down` | 340 | | 87 s |
| host git | 5288 | | 23 s |

First starts and builds are 870 of the 1550 thread-seconds. First starts
at the warm cost (pinfold #63) save about 460, and no `localhost/` pull
retries (#64) about 190: just under 4 minutes, inside the 5-minute budget.
