# Y-153 closed candidate gate inputs

The 2026-10-14 operator decision trusts Pinfold's documented stable launch
contract. This implementation uses that boundary. It does not restore the
withheld observer draft or treat its evidence as validation. Previous evidence
remains outside this candidate.

`closed_inputs` is an optional frozen gate declaration. Its nonempty token
names relevant operator runtime configuration and asserts that the command
has no inputs beyond the recorded sources. Existing admission, definition
adoption and consumer qualification carry it. There is no new lifecycle.
The first supported consumer is a candidate boxed command with no egress,
no selected host variables, known typed suppliers and supported observed
runtime/image identities. Missing declarations and all other consumers remain
ineligible for reference reuse. Command stdout is never identity evidence.

Environment identity uses source references, not values or fingerprints.
The boxed gate definition is bound to the running Yard executable. The base
is already a candidate input; image defaults are bound to the observed image.
Memory and the operator declaration cover relevant launch configuration.
The semantic record excludes box handles and consumer labels, while original
launch evidence retains its full policy and provenance. Equivalent declared
commands on the same input can therefore match across actual launches.
There is no reference lookup or landing reuse in this change.

`dc1dfc13d1c3c01ca466f33a14e1298e349da812`.
The public architecture states that caller-owned `box up` takes environment,
egress and resources from the spec, and reports the resolved image at ready.
`cli.rs` doctor reports runtime backend followed by its version. The runtime
trait obtains that version from the runtime CLI's `--version`.

Yard reads its existing bounded Pinfold version interface and drains doctor
one bounded line at a time, retaining only supported backend/version fields.
It discards diagnostics and the remaining report. An unsupported format or
failed observation stays unknown. Pinfold version changes are semantic input
changes. These public sources establish the supported interface; they do not
prove the installed executable came from that source. Maintaining the runtime
contract, including declaring relevant configuration changes, is the operator's
responsibility. No runtime upgrade was performed.
