# Y150 selective reference audit

This records the expansion after the first mechanism in e0272d9.
The G2 scenario remains independently runnable as
`candidate_reuses_original_pass_after_bookkeeping_with_unknown_rerun`.

Command-only adoption runs the changed gate and retains the other gate's
original check through an explicit launch reference. A separate change to
the closed-input token invalidates the declared runtime/tool configuration
of that gate. Fixture command counts supply the expected selectivity.
Dropping command or declaration identity, or rerunning unrelated consumers,
breaks these blocks. Older adoption cases do not observe explicit references.

Image adoption changes real Dockerfile ENV bytes. All boxed gate commands
run again. Host Git supplies the selected Dockerfile blob. The original
execution, result and check snapshots remain unchanged. Ignoring the image
or consuming an unselected source breaks this block.

The existing G2 `quiescent_plan_cas_retains_only_exact_node_and_producer_evidence`
blocks continue to cover independently adopted extensions, skills, agent
settings, staging and image contexts, their real model counters, and the
actual suppliers of panel consumers. Gate-only adoption there retains its
implementer supplier. Skill and image adoption there may replace it.
Those blocks remain unchanged; they cover the same definition matcher used
by current reference qualification and avoid duplicate assertion blocks.

A new failed command, selected with operator failure handling, cannot match
an old passing command. Its acceptance leads to approval beside a referenced
pass and an omitted gate. A later no-change implementation runs the failing
command again and requires a second exact decision. Fixture counts prove
that failure acceptance cannot authorize reuse. MCP distinguishes the failed
judgment, the passing reference and the absent skipped execution.
Failed execution/result/check and resolved decision snapshots stay unchanged
through landing and reopening. Carrying acceptance or copying a pass fails
these blocks. Earlier acceptance tests have no matching reference candidate.

The final approval names the current base, head, proof, ticket and plan
revisions and explicitly accepts its omitted node. Its check selection keeps
the original referenced check through the real queue. Git proves the selected
candidate landed. Comparing the approval's check IDs with its attention
selection establishes their agreement, rather than deriving expected policy
from Yard's logic. Existing G2 live approval/protected-path policy controls
continue to cover authorization changes without new verification.

All waits consume future attention/landing events. Retained events are not
used for a replacement approval. The Pinfold wrapper preserves subprocess
exit status. No sleeps, retries, runtime stubs or public model endpoints are
added. No assertion or binary lines are deleted, and no guarantee is weakened.
This is the test-audit change gate, not a whole-tree sweep.

Worker validation is fmt and clippy. Native host e2e and sabotage execution
remain the operator's gate, as required by the ticket.
