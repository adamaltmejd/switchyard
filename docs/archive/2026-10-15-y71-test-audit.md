# Y-71 integration test gate

Added two host e2e scenarios in `g09_integration.rs`. They use the real Pi
harness, real boxes and the scripted host model. No public endpoint, sleeps,
retry loops or binary barriers are added. No existing assertions are changed
or removed. The suite is not run in the worker box; the operator requested
fmt and clippy here and the real host suite at the landing gate.

## Dispositions

- Keep `integration_retains_partial_work_and_approves_only_its_output`.
  G2's integration publication clause and G9's retained integration workspace
  clause describe it. Fixture A and B change separate files. A real integration
  tool merges A and writes a partial file before a host-model latch holds its
  next reply. Before restart, the store still shows the owner running and the
  host file proves partial work. A new execution imports B in that same clone.
  Host Git verifies C's contents. A real candidate gate requires both source
  files and the retained partial file. A source snapshot write exits with the
  fixture's refusal code while C's own write succeeds. Approval naming A's
  Git head refuses as stale with the exact supplied/current heads and no
  approval row. C's exact approval succeeds, and only C lands.
- Keep `integration_conflicts_require_repair_before_selection`. G2/G9's
  conflict clause describes it. A and B add conflicting versions of one file.
  Git's unmerged entries prove the retained conflict. Dirty attention, no
  selection and no approval prevent fallback to either source. Explicit
  continuation resolves the same merge and reaches approval on C. This is
  the positive control in the same project.

## Gate answers

The test comments name sabotage: mount canonical into the integration writer,
make inputs writable, reuse A's candidate or approval, recreate the partial
clone, publish a dirty merge, or select a source after integration failure.
Existing independent-writer tests never import two source publications into
one new candidate. Existing dirty-tree tests have no integration dependencies
or source candidates that could accidentally become selected. The held
restart and unresolved merge are the hard cases for these mechanisms.

Expected file bytes, refusal exit code and selected names come from the
fixture. Expected source heads come from host Git's immutable publication ref.
The approval identity comparisons establish agreement between the supplied
Git identity and the daemon's current candidate. Store queries observe
ownership, selection and approval from outside the binary. No yard internals
are imported. Neither new scenario has an assertion twin in the existing
writer, selection, dirty-tree or restart scenarios.

No operator decision is needed to remove or weaken a guarantee. None is
removed or weakened. Test lines removed: 0. The duplicate selector snapshot
staging block is replaced by the shared read-only candidate staging path;
no other binary behavior is deleted.
