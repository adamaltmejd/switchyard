## Dispositions and operator list

Keep the three new G4 scenarios in `g04_capacity_holds.rs`:

- `racing_workers_share_one_execution_slot`: G4's shared-slot race.
  Reserving after spawn or counting only attempt lanes breaks it. Both
  tickets are admitted concurrently with two lanes and one effect slot.
  The host model's held request and pinfold's box list observe the acting
  worker. The waiting event names the other execution; its identity must
  differ from the box owner's row. The limit and expected one worker come
  from the fixture config. Both approvals after release are the allowed
  control. The existing race tests attempt admission, not effect admission.
- `one_slot_lands_with_child_gates_and_excludes_a_worker`: G4's serial
  ticket at limit one and host-versus-box exclusion. Retaining a dormant
  parent slot, counting only boxes or releasing before host exit breaks
  it. A real host gate holds on FIFOs after the reviewed candidate's
  approval released its lane. The fixture FIFO, host marker file and
  scripted model requests observe effects. The configured gate names and
  marker contents are expected values from the fixture; canonical git
  provides the landed bytes. The second worker's approval is the allowed
  control. G7's end-to-end scenario has spare landing capacity and cannot
  expose a parent/child deadlock at one; G10 tests queue order, not shared
  capacity.
- `an_old_host_child_retains_capacity_across_restart`: G5's surviving
  host child and G4's retained capacity. Releasing on daemon death or row
  end, or dropping the pre-box Git child's inherited lock breaks it. The
  daemon is killed while the real Git wrapper holds the clone call on a
  FIFO. Before restarting, the host proves that exact PID still exists
  and the store proves execution 1 is running, reserved and has no box
  handle. After restart, attention names that execution with `ownership`;
  the new execution waits and the host model has no requests. Only after
  releasing the wrapper does the second ticket reach approval and the old
  reservation clear. Expected identities and counts come from the first
  execution in the fresh fixture, the PID reported by the host wrapper,
  and the configured limit. G5's existing host-gate restart kills its
  recorded group at startup; it cannot catch an old owner that survives.
