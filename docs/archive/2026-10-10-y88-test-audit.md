# Y-88 assertion audit

Gate audit of the changed G7 and G8 blocks. No suite sweep or host e2e run
was performed in the worker box. The ticket reserves runtime verification
for the operator's exact-head host check and landing gate.

## Dispositions

- G7 ordinary round trip: extend the existing scenario. Advance the target
  before approval so merged and candidate inputs differ. Keep the landing,
  proof, audit and cleanup assertions. Inspect durable node/input/result
  evidence after cleanup through the CLI and store.
- G8 interrupted publication: extend the existing held-seat restart.
  Keep the once-only publication assertions. Inspect the ineligible live

## Gate answers for the operator

G7 establishes the new ordinary-chain binding clause in its Shown by row.
Its observers are `attempt show --json`, the SQLite store, git and the host
proof snapshot. Expected node names, output types, revision 1 and the pass
verdict come from the literal fixture configuration and scripted workers.
Candidate identity comes from git in the worker clone, with its fixture
file and parent independently checked. Target identity comes from git in
the operator checkout. Merged identity and parents come from canonical git.
Proof identity comes from the host snapshot containing the fixture's bytes.
Execution and publication IDs are compared only to establish reference
agreement, including agreement between CLI and store after cleanup.

Sabotage: attribute a result to another node or input, omit the producer
reference, or feed a landing gate the candidate rather than the merged ref.
The prior G7 blocks only inspected native check identity and cleanup; they
could not detect absent or misattributed graph evidence. G6's descriptive
plan and gate-input assertions do not inspect these durable node results.
The target advance and cleanup make this stronger than a first-run
fast-forward where the two commit identities coincide.

G8 establishes the new held-publication eligibility clause in its Shown by
row, using G5's existing ownership reconciliation. Its observers are CLI
inspection, the store while the daemon is dead and the status history.
The fixture publishes a literal pass, attempts a refused second publication,
then holds its next model request until the test releases it. This is the
point held through the kill. Before restart the store proves the pass
publication remains, the execution is running, its result is null and
checked teardown is false. Restart must reach approval with one review
execution, declared `complete`, infrastructure `interrupted`, checked
teardown and an eligible verdict referring to that original publication.
The declared pass and interruption come from the fixture and deliberate
daemon kill. Binding and publication comparisons prove preservation.

Sabotage: bind a result at publication, or attribute the reconciled result
to a new execution or another node/input. The prior block proved that the
publication survived but did not observe result eligibility. G7 observes
normal end; it cannot establish the separation across a crash. The same
project supplies the positive control: the originally held publication
becomes eligible after reconciliation and reaches approval. No new hook,
sleep, retry, timeout scenario or public model endpoint was introduced.

## Implementation evidence

The migration adds nullable node, input, result and teardown columns without
backfilling history. Start binds admitted ordinary nodes. End stores declared
output and infrastructure evidence separately. The existing capacity release
transaction marks teardown only after its box-absence and host-lock proofs.
The one result eligibility predicate serves CLI inspection, producer lookup
and current checks. Reconciliation and ownership reaping use the same end
and release paths; publication is unchanged.

Gate results retain the observed completion, stop or timeout separately from
their verdict. Review results retain the runner's completion, failure, stop,
timeout or unknown terminal state separately from any publication. Existing
execution outcome strings and native decision behavior remain unchanged.

Worker checks passed: `cargo fmt --check` and
`cargo clippy --all-targets --locked -- -D warnings`. The latter compiled the
changed e2e scenarios. Runtime assertions and sabotage execution await the
host gate; no e2e test was run here.
