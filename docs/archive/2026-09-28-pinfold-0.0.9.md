# pinfold 0.0.9 on the e2e suite

This follows `2026-09-28-pinfold-maintenance-pass.md`, on the same host
and suite, now 56 scenarios. It moves pinfold from 0.0.8 to 0.0.9, which
closes pinfold #68, #69 and #70.

## Changes in Yard

None, in the binary or the harness.

- **#68:** `image rm NAME` now untags NAME even while another name's box
  runs the image. The harness teardown already retired each name its
  daemon built. Under 0.0.8, about 30 of them kept their tags each run.
  In this run, the teardown made 53 `image rm` calls for 53 names, and
  none of the names kept a tag. The host's other `pinfold/image-*` tags
  were 302 before the run and 302 after.
- **#70:** pinfold now finds the container runtime on the host's `PATH`,
  not the box spec's. On macOS, the `PATH` Yard gives a gate box hid
  Homebrew's `container`, so every gate box failed to start. This host
  never showed the bug, because `podman` is in `/usr/bin`. The macOS run
  is still to be done.
- **#69:** the maintenance pass lists boxes and images once. The shared
  state dir already paid for the pass once per day, so this run never
  ran it.
