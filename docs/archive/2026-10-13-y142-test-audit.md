# Y-142 test-audit Gate

This changes G2's existing
`quiescent_plan_cas_retains_only_exact_node_and_producer_evidence` scenario.
The architecture's revision clause and G2's Shown by row now name independent
ordinary candidate source adoption. This is a Gate review, not a suite sweep.

The changed blocks answer the Gate questions:

- Gate definitions: after completed gates and reviews, adopt one committed
  command. A host file records the original and adopted invocations. The
  unrelated gate's host counter and completed review check stay selected.
  Overwriting adopted definitions in `resolved`, or invalidating the whole
  panel, breaks these observations. Earlier profile edits did not change a
  command definition independently of runner policy.
- Reviewer settings: adopt the declared review agent's model setting without
  changing the graph or staging. Both seats using that agent must run the
  fixture's new model. The host model observes actual requests; the store
  records the same literal settings. Earlier profile selection changed the
  runner and settings together. Gates must remain completed.
- Staging: adopt extension bytes, then skill bytes, in separate revisions.
  Host model opening counters require both affected seats to run at each
  revision and expose the fixture markers. Each consumer needs a new digest;
  selected source blobs come from host Git. Reusing stale tool or skill
  identities fails these blocks. The original image commit, Dockerfile blob
  and entire context tree come from host Git before any adoption and remain
  fixed. The former new-admission block changed staging and image together;
  it could not distinguish these failures.
- Bindings and history: the final seat's verdict input names the actual
  first-seat execution, node and result output. Its value agrees with that
  immutable result. Store snapshots preserve all pre-adoption execution,
  result, check and revision rows, plus original admission and ticket.
  Stale source edits and decisions name expected/current plan revisions and
  write no audit row; corrected identities succeed in the same project.
  The existing held stale-edit block also snapshots every mutable table.
- Approval: a real held worker owns the sole execution slot before approval.
  Landing cannot establish an intent. Source adoption withdraws that queued
  approval before release and replacement checks. Final landing executes the
  original command, as shown by its host counter. There is no crash scenario
  or test-only binary barrier.

These are the completed-candidate cases, where stale evidence can wrongly
survive. G6's frozen-source/template-sync and whole-source admission coverage
and G11's safeguard-sync coverage remain the survivors for those mechanisms;
no twin was added. Existing ownership and checked-handoff coverage remains.
The mixed staging/image new-admission block was replaced with independent
active adoption, without removing a guarantee. Test source lines removed: 38.
Binary source lines removed: 19. Neither count represents a removed control.

Validation: `cargo fmt --check` and
`cargo clippy --all-targets --locked -- -D warnings`. Host e2e and independent
named runtime sabotages remain post-approval gates. They were not run here.
Required sabotage runs are resolved overwriting adopted definitions, stale
tool identity, stale skill identity, and whole-panel invalidation for a gate.

Y-140 retains its original prerequisites and integration obligation. Y-142
does not qualify changed implementer settings, held startup or definition-only
implementation handoff. Y135 Proposal360, Check1340 P3, Y139 Check1348 P3 and
Check1356 P2 remain carried into parent integration. Y-137, Y-136, Y-109 and
Y-62 remain required. Ordinary implementation adoption, independent image and
landing-policy adoption, and packaged activation stay with their admitted
dependent children. This commit does not complete those parents.
