# Y-68 implementation and test audit — 2026-10-14

This candidate implements the original Y-68 scope after the documentation-only
candidate was blocked. The earlier scope-split note records a proposal, not
delivery. No operator scope change was assumed. ARCHITECTURE.md now describes
the implemented operator operations and restrictions.

The execution table is rebuilt by a forward migration with nullable attempt
and scope. Existing IDs, foreign keys and every old column are copied. Foreign
keys are checked before commit. Historical scope stays null. Ordinary execution
consumers require their attempt; optional standalone associations are excluded
from attempt controllers and cleanup. There is no synthetic ticket, attempt,
second execution entity or owner mechanism.

Operator stdio starts commands and ordinary read-only reports against a full
committed input and frozen target policy. The original lifetime bounds capacity
waiting, startup and work. Shared reservation, inherited host lock, box teardown
and restart reconciliation apply. Restart interrupts after checked ownership;
it does not replay. Interrupted raw reports remain distinct from completed typed
results. Final usage stays on the execution, with unknown and partial fields
preserved. Commands retain actual exit codes, including failed verdicts; report
failures retain a known subprocess exit code without supplying a completed result.

Changed scenarios were read end to end, including selected read-only resolution,
operator versus worker calls, held crash proof, nullable associations, controls,
eligibility, counters and cleanup. Narrow searches covered schema/store/result
observers and attempt consumers. Retained events use history.find; sequential
future events use history.until. Operator clients are replaced after restart.
Pinfold wrappers delegate the real command and propagate its subprocess status.
No test introduces a sleep, retry, timeout-as-pass or binary barrier.

The diff removes 128 test lines and 100 binary lines through replacements and
fixture/helper refactoring. No assertion block was deleted. The new standalone
runner is included in the added binary lines.

them for the host landing gate after approval. This audit is static evidence,
not a claim that the native scenarios passed. No development daemon opened the
construction project or its backlog; no .yard configuration was changed.

`cargo clippy --all-targets --locked -- -D warnings`, `cargo build --locked`,
and `git diff --check`.
