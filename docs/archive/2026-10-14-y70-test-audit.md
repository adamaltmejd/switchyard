## Dispositions

Keep `g08_selects_existing_candidate::only_the_declared_choice_is_checked_and_landed`.
It establishes the new G2 and G8 selection clauses. Five differently configured
real Pi implementers hold independent clones concurrently on one frozen ticket.
Each writes disagreeing fixture content and proof. The same reviewer profile
publishes nonblocking raw findings for every candidate. The read-only picker
consumes all ten declared results and selects B. B publishes before the final
producer, so choosing the newest publication fails the fixture's native gate.
Host Git supplies candidate heads; fixture bytes supply content, proof agreement
and review text. Store rows and real operator MCP expose supplier, producer and
choice bindings. The native candidate gate and canonical Git are the downstream
observers. Approval requires B's own review and native gate, not losing reviews.

The same scenario refuses a foreign operator reference without an audit write,
then accepts B in that project. A second same-head choice makes the prior
approval identity stale. Replacing B makes the current choice stale, requires
new proof/head/check evidence and preserves old execution, check and finding
rows. Quiescent reopening preserves exact choice approval and queue landing.
The test names the sabotages: newest-head selection, picker privilege,
copied losing verdicts, superseded choice reuse, historical mutation and
approval without choice identity. Failed source/proof writes are observed from
the real picker box, followed by successful publication in the same execution.
Existing writer-capacity and isolation scenarios stop at `stopped:candidates`;
ordinary review scenarios have no picker or alternative producer. They cannot
observe these choice and selected-only consumer failures.

Keep the historical-store extension in
`g15_plans_and_proposals::nullable_execution_upgrade_preserves_real_results_approvals_and_owners`.
Its two existing archived source binaries already create, approve and land real
candidates. Expected historical rows come from those stores before upgrade.
Only the new absent `choice` fields are expected to be null. Every previous
field still compares exactly through two reopens, alongside foreign-key and
canonical Git observations. Inferring a picker from a historical head fails
this block. Fresh selection history cannot expose that migration error. This
uses existing historical cases and adds no compatibility framework or lifecycle.

Keep `candidate.selected` in G7's closed spec-event list. The binding Store
contract names that new event. No existing event or assertion is removed.
