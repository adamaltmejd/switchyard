# Y150 candidate reference audit

The new independently runnable G2 scenario is
`candidate_reuses_original_pass_after_bookkeeping_with_unknown_rerun`.
It uses real Pi workers, real boxes, CLI/store observations and operator MCP.
No test-only binary path is added.

The first assertion block compares fixture-owned command and model counts
after a ticket edit and a new no-change implementation. Host Git supplies
the candidate trees. The fixture supplies proof bytes. Rerunning every gate,
matching only heads, or accepting undeclared inputs breaks the counts.

The second block observes the original execution/result/check reference,
absence of a second judgment or check, and the exact new operator identity.
Copying a pass or treating reuse as skip breaks those observations.
Existing definition-adoption tests keep the same implementer supplier and
cannot establish reuse after a new publication.

The proof-only and tree-changing edits are negative controls in the same
project. They run the declared commands again. Their expected trees come
from Git, and their expected counts and proof changes come from the fixture.
Old execution and check snapshots remain unchanged across these edits.

The scenario consumes future approval events with `approval`, rather than
finding a prior approval in retained watch history. Command counters are
recorded at the real Pinfold exec boundary. The wrapper falls through to
`exec "$REAL" "$@"`, preserving the real subprocess exit status. A command
failure cannot reach the asserted approval boundary.

No assertion or binary lines were removed. Existing definition-adoption,
accepted-failure and skipped-node scenarios remain in place. This is the
test-audit change gate, not a whole-suite cleanup sweep. The operator has no
proposed weakened guarantee to decide.

Validation: fmt and clippy run in the worker. Host e2e, including sabotage
runs, is deferred to the native landing gate as the ticket requires.
